## 审查结论

## 代码问题

### P1：下载时间预算无法约束一次 HTTP 分块读取

位置：[inputs.py](../../src/ai_inference/service/inputs.py)，`download_image` 第 121–137 行。

截止时间只在 `response.read1()` 前检查。标准库在解析分块头、分块分隔符时可能执行多次底层读取；远端持续缓慢发送数据且每次间隔低于 socket timeout 时，单次 `read1()` 就能超过剩余预算。另一个路径是远端返回 `Connection: close`：`getresponse()` 会清空 `connection.sock`，响应仍持有连接，当前逻辑无法更新它的超时。响应头读取也未受整个下载预算约束。

验证：使用真实标准库 `HTTPResponse` 和模拟逐字节传输，每字节延迟 0.005 秒，发送带 100 个前导零的合法分块长度。设置 `url_timeout_seconds=0.1`，实际约 0.64 秒后才返回 504。此验证未访问外网；它确认 HTTP 解析内部读取不能被外层循环及时约束。

影响：一个慢速公网源可以延长占用唯一执行名额，其他推理请求持续返回 503。DNS 耗时不受预算控制是已说明的限制，但此问题发生在 DNS 之后。

建议：让剩余截止时间约束每次实际网络读取及连接/TLS/响应头阶段，覆盖响应持有 socket 的情况；保留公网 DNS 校验、固定 IP、原域名 TLS 校验、拒绝代理和重定向的行为。不能只在返回后检查时间，也不能用后台下载继续运行、提前释放执行名额的方式伪造取消。增加慢分块头、慢响应头、连接关闭和超时后恢复准入的回归。

### P2：客户端关键点错误返回模型故障 500

位置：[runtime.py](../../src/ai_inference/service/runtime.py)，`Runtime.predict` 第 35–47 行；[schemas.py](../../src/ai_inference/service/schemas.py)，`ImageMetadata`。

只校验五点数量与有限数值，没有验证当前模型是否消费关键点，也没有验证 SFace 的退化关键点。任何带关键点的请求都被转换成 `FaceInput`。普通 YOLO 管道在 `pack` 拒绝未消费关键点；SFace 对重合或共线关键点拒绝对齐，异常均被 `execute` 转为 500 且丢失图片索引。

真实 CPU 模型验证：YOLO11 正常图片返回 200，附加五个有效关键点返回 500；SFace 正常五点返回 200 和 128 维特征，五个重合点返回 500。后者只验证接口执行，不代表人脸识别精度。

建议：在调用模型前按预处理能力校验关键点，拒绝不支持关键点的模型输入；对需要对齐的输入验证与 SDK 一致的几何约束，返回带图片索引的 422。`aligned_input=true` 且未传关键点时，也应提前验证 112×112 裁剪要求。避免把所有模型 `ValueError` 一概转换成 422，以免隐藏真实执行故障。补齐四种输入、退化点、对齐裁剪和批量原子性回归。
